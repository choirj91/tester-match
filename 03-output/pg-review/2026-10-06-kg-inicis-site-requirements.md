# KG이니시스 재심사 대응 — 홈페이지 수정 요건 (2026-10-06)

> 목적: NHN KCP 반려 뒤 KG이니시스(포트원 경유)로 재신청하기 위해, 사이트·정책·결제 코드·심사 자료를 어떻게 바꿀지 한 문서에 모은다. 이 문서를 기준으로 수정 작업을 나눈다.

## 3. 가격·BM 변경 — 1명당 1,100원 (결정 필요)

### 3.1 운영자 의도

- 1,100원 = **테스터 보상분 + 운영 수수료** 로 보이게 한다. "회사는 수익이 아니라 운영비용만 쓴다"는 메시지로 사용자 신뢰를 얻는다.

### 3.2 숫자 (결정 필요)

이 메시지를 **문자 그대로** 지키려면 보상 상한을 올려야 한다. 지금 보상 상한은 시트당 700 크레딧(ADR-0014: 설치 100·출석 20/일·7연속 +50·완주 +120·개근 +50·출시 +100).

| 안 | 1,100원의 구성 | 메시지와의 일치 | 시트당 회사 몫(추정) |
|---|---|---|---|
| A. 보상 상한 1,000 크레딧 | 보상 1,000 + 운영 100 | "운영비용만" 그대로 성립 | 100 − PG 수수료(1,100 × 약 2~3.5% ≈ 22~39원) ≈ **61~78원** + 미완주로 지급되지 않는 보상 |
| B. 보상 상한 700 유지 | 보상 최대 700 + 운영 400 | "운영비용만" 이라 쓰기 어려움 → "보상과 운영비" 수준으로 완화 | 400 − 수수료 ≈ 361~378원 |

- A 를 고르면 ADR-0014 의 마일스톤 표를 1,000 기준으로 다시 짠다(예: 설치 100·출석 30/일(×14 = 420)·7연속 +80·완주 +200·개근 +100·출시 +100 = 1,000). 숫자는 결정 뒤 확정.
- 기프티콘·네이버페이 포인트 매입가는 액면가로 가정(할인 매입 가능하면 회사 몫 증가).
- PG 수수료율은 이니시스 계약서 기준으로 확정(영세·중소 가맹점 우대율이면 더 낮다).
- 1,100원은 부가세 포함 소비자가로 표기한다(공급가 1,000 + 부가세 100 으로 읽힐 수 있으니, 결제 페이지에는 "1,100원(부가세 포함)" 으로 명시).

### 3.3 잠금 결정과의 충돌

- CLAUDE.md 잠금 결정 3 "1매칭 = 1,000원(테스터 800 + 플랫폼 200)" 과 충돌 → **ADR-0017 추가** 후 CLAUDE.md 표 갱신, 그 뒤에 코드(`PAID_TESTER_PRICE_KRW`)·정책 문구 변경.
- "1원 = 1 크레딧" 은 유지한다.

## 4. 결제 페이지를 "오픈 대기"로 공개 (결정 필요: 공개 범위)

### 4.1 지금

- `/paid-testers` 는 비로그인·일반 회원에게 "곧 오픈합니다 — 결제 연동 마무리 중" 박스만 보이고 주문 폼이 없다(`PAID_TESTERS_PUBLIC_ORDERING = false`). 심사자가 로그인 없이 보면 상품이 없는 사이트로 보인다.

### 4.2 바꿀 것

- 비로그인에게도 **상품·가격(1,100원)·진행 방식·환불 기준·사업자 정보**가 전부 보이게 한다. "곧 오픈" 박스 제거.
- 로그인 회원에게 주문 폼(앱 선택·인원·유의사항 동의)을 보여 준다.
- 결제 버튼 동작은 아래 중 하나(결정 필요):

| 안 | 심사 기간 동작 | 장점 | 단점 |
|---|---|---|---|
| ① 전면 오픈 | 모든 회원이 결제창까지 진행. 실결제는 라이브 키 전환 전까지 이니시스 **테스트 채널** | 심사자에게 완전한 라이브로 보임 | 이니시스 테스트 상점은 실카드를 승인했다가 자동 취소하는 방식으로 알려져 있어 일반 회원이 혼란을 겪을 수 있음(확인 필요). 라이브 전환 때 테스트 주문 정리 필요 |
| ② 오픈 대기 (권장) | 주문 폼·가격 전부 공개. 심사 계정·관리자는 결제창까지 진행. 그 외 회원은 결제 버튼에서 "결제 오픈 준비 중 — 오픈 시 알림" 안내(원하면 알림 신청 수집) | 일반 회원 혼란 없음. 심사자(테스트 계정)는 실제 결제창을 봄 | 심사자가 테스트 계정 없이 보면 버튼 문구에서 "준비 중"이 보임 |

- 라이브 키 전환과 동시에 ②의 안내를 걷고 전면 오픈한다.

## 5. 크레딧 정책 재정의 + 보상 교환 상점

### 5.1 크레딧 규칙 (정책·약관·화면 공통 문구)

1. 크레딧은 **테스터 활동 보상**으로만 적립된다(설치·출석·완주 등 마일스톤).
2. 크레딧은 **구매할 수 없다**. 카드 결제·계좌이체·어떤 결제수단으로도 크레딧을 얻을 수 없고, 결제한 금액은 크레딧으로 바뀌지 않는다.
3. 크레딧은 **양도·교환(회원 간 이동)할 수 없다**.
4. 크레딧은 **현금으로 환급되지 않는다**.
5. 크레딧은 보상 교환 상점에서 **기프티콘 또는 네이버페이 포인트**로 바꾸거나, 본인 앱의 테스터 시트를 여는 데 쓸 수 있다(결정 필요: 시트 결제 용도 유지 여부 — 유지하면 "보상으로 적립한 크레딧으로도 시트를 열 수 있습니다" 로만 표기).
6. 만료·페널티 차감 규칙은 현행 유지.

### 5.2 보상 교환 상점 페이지 (신규, `/rewards` 가칭)

- 목적: "테스트하면 이런 보상을 받는다"가 한눈에 보이게 — BM 을 심사자와 테스터 모두에게 보여 준다.
- 구성: 보상 항목 카드(예: 카카오 기프티콘 1,000·3,000·5,000원권, 네이버페이 포인트 1,000·5,000), 각 항목의 필요 크레딧, 신청 버튼(로그인 필요), 처리 기간(영업일 3일), 월 교환 한도·최소 교환 단위.
- 상단 고정 안내: "보상은 회사가 비용으로 지급합니다. 크레딧은 구매·양도·현금 환급이 불가능합니다."
- 네이버페이 포인트: 지급 API 는 별도 제휴가 필요하므로 **초기에는 운영자가 네이버페이 포인트 쿠폰(상품권)을 사서 수동 지급**. 화면 문구는 "네이버페이 포인트(쿠폰 지급)". 제휴 전까지 "준비 중"으로 둘지는 결정 필요.
- 기존 `credit_redemptions`·`/admin/redemptions` 처리 흐름을 그대로 쓰고, 교환 항목 목록만 추가한다.

### 5.3 크레딧 정책 페이지에서 삭제·수정

- **제5조 "외부 포인트 전환 — v3" 삭제** (환금성 신호 1순위).
- 제3조(사용 방법)에 5.1 의 규칙 1~5 를 그대로 넣는다.
- "환급" 이라는 단어는 모두 "복구"(사용한 크레딧을 잔액으로 되돌림) 또는 "보상 교환"으로 바꾼다.

### 8.1 서비스 설명서(1장, 제출용 초안)

- **판매 상품**: 테스터 시트(비실물 서비스). 1명당 1,100원(부가세 포함), 1~30명 선택, 건별 결제. 테스터는 14일간 실기기에서 앱을 실행하고 매일 스크린샷으로 체크인합니다.
- **판매 주체**: 낰낰컴퍼니(사업자 441-20-02677)가 직접 판매하고 직접 환불합니다. 테스터에게 현금을 정산하지 않습니다(2차 정산 없음).
- **테스터 보상**: 테스트 활동에 따라 회사가 크레딧을 지급하고, 테스터는 이를 기프티콘·네이버페이 포인트로 교환합니다(회사 비용). 크레딧은 구매·양도·현금 환급이 불가능하며, 결제 금액이 크레딧으로 전환되는 경로는 없습니다.
