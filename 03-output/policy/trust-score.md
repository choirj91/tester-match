# 신뢰도(Trust Score) 정책 v1

> 결정 기록: [ADR-0010](../../01-source/decisions/ADR-0010-trust-score-policy.md)
> 코드 단일 소스: `03-output/app/src/lib/trust.ts`
> 시행일: 2026-07-24 (소급 적용 없음 — 시행일 이후 이벤트부터)

## 1. 목적

"14일 완주"라는 품앗이의 핵심 약속을 지키는 테스터가 눈에 띄고 우대받게 한다.
점수는 **완주 이력의 요약**이며, 활동량(앱 등록 수·게시글 수)의 지표가 아니다.

## 2. 점수 체계

| 항목 | 값 |
|---|---|
| 시작 점수 | **50** |
| 범위 | 0 ~ 100 (clamp) |
| 기록 | 모든 증감은 `trust_score_history`에 원장 기록 (delta, score_after, reason, ref) |

## 3. 증감 규칙 (v1)

| 이벤트 | 증감 | reason 코드 | 트리거 지점 |
|---|---|---|---|
| 14일 완주 (체크인 14회 달성) | **+5** | `reward.completion` | 14번째 체크인 API |
| 자진 중도 포기 (옵트아웃) | **−3** | `penalty.opt_out` | 옵트아웃 API (버튼에 사전 고지) |
| 무단 이탈 (기간 만료 미완주 또는 5일 연속 미체크인) | **−10** | `penalty.no_checkin` | penalty-sweep cron |
| 관리자 수동 조정 (어뷰징 제재 등) | 임의 | `admin.adjust` | 수동 SQL (history 필수) |

**설계 근거**
- 완주 +5: 10회 완주 = 만점 도달 (50→100). "꾸준함"이 수개월 걸려 쌓이는 속도.
- 옵트아웃 −3 < 무단 이탈 −10: 포기하더라도 **알리고 나가는 게 항상 유리**하도록 격차 유지. 개발자는 정원이 즉시 복구(required_testers +1)되므로 조기 통보가 실익.
- 완주 1회(+5)가 옵트아웃 1회(−3)를 상회: 실수 한 번이 성실 이력을 지우지 않게.

## 4. 가점을 주지 않는 것 (어뷰징 방지)

- 앱 등록 수 — 자기 앱 양산으로 점수 조작 가능
- 게시글·댓글 — 도배 유인
- 매칭 신청(옵트인) 자체 — 신청 후 방치가 최악의 행동이므로 신청만으로 보상 금지
- 일일 체크인 개별 가점 — 완주(+5)에 수렴시켜 부분 체크인 파밍 차단

## 5. 노출·활용

| 위치 | 내용 |
|---|---|
| 전 서비스 닉네임 옆 `★N` | 상시 노출 (게시판·댓글·browse·프로필) |
| `/stats` 신뢰도 랭킹 | **50점 초과자만** TOP 20 (기본값 50 그대로인 유저는 미노출 — 감점자 조리돌림 방지) |
| 매칭 우선권 (v1.1 예정) | 급구·인기 앱 정원 경쟁 시 신뢰도 높은 순 우선. 매칭 엔진 가중치 도입 시 반영 |
| 크레딧 보상 연동 (예고됨) | `/stats` 배너로 예고. 지급 기준·주기는 별도 설계 (잠금 결정 #3 크레딧 원장 준수) |

## 6. 이의·복구

- 감점 이의: 관리자가 `trust_score_history` 원장 확인 후 `admin.adjust`로 정정
- 자연 복구: 별도 시간 경과 복구 없음 — 완주로만 회복 (v2에서 "최근 90일 가중" 검토)

## 7. v2 후보 (미시행)

- 최근 90일 이동 가중 (오래된 감점 희석)
- 등급 뱃지 (70+ 우수 / 90+ 최우수)
- 신뢰도 기반 매칭 정원 선점, 크레딧 보상 배율
