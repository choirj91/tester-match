# 신뢰도(Trust Score) 정책 v1.1

> 결정 기록: [ADR-0010](../../01-source/decisions/ADR-0010-trust-score-policy.md)
> 코드 단일 소스: `03-output/app/src/lib/trust.ts`
> 시행: v1 2026-07-24 (완주 +5) → **v1.1 같은 날 개정 (체크인 +1, 상한 1,000)**. 소급 적용 없음.

## 1. 목적

매일의 체크인이라는 품앗이의 실제 행동이 곧바로 점수로 보이게 한다.
점수는 **성실한 체크인 이력의 누적**이며, 활동량(앱 등록 수·게시글 수)의 지표가 아니다.

## 2. 점수 체계

| 항목 | 값 |
|---|---|
| 시작 점수 | **50** |
| 범위 | 0 ~ **1,000** (clamp, DB CHECK 제약) |
| 기록 | 모든 증감은 `trust_score_history`에 원장 기록 (delta, score_after, reason, ref) |

## 3. 증감 규칙 (v1.1)

| 이벤트 | 증감 | reason 코드 | 트리거 지점 |
|---|---|---|---|
| 일일 체크인 1회 | **+1** | `reward.checkin` | 체크인 API — `UNIQUE(match_id, day_n)` 통과 시에만 (하루 1회 강제) |
| 자진 중도 포기 (옵트아웃) | **−3** | `penalty.opt_out` | 옵트아웃 API (버튼에 사전 고지) |
| 무단 이탈 (기간 만료 미완주 또는 5일 연속 미체크인) | **−10** | `penalty.no_checkin` | penalty-sweep cron |
| 관리자 수동 조정 (어뷰징 제재 등) | 임의 | `admin.adjust` | 수동 SQL (history 필수) |

**설계 근거**

- 체크인 +1: 행동과 보상의 즉시 연결 — 14일 완주 = +14. 만점(1,000)까지 950회 체크인 ≈ 68회 완주 분량. 장기 순위 경쟁 여지 확보.
- 옵트아웃 −3 < 무단 이탈 −10: 포기하더라도 **알리고 나가는 게 항상 유리** (정원 즉시 복구 실익).
- 동시 매칭 N개면 하루 최대 +N — 실제 테스트 N개를 수행 중인 것이므로 정당 적립으로 간주.

**알려진 트레이드오프 (모니터링 항목)**

부분 체크인 후 무단 이탈 시 순이익 가능 (예: 13일 체크인 +13 − 이탈 10 = +3).
"열심히 하다 마지막에 놓친" 케이스와 구분이 어려워 v1.1에서는 허용.
잠수 직전 파밍 패턴이 관측되면 이탈 페널티 상향(−15~−20) 또는
"미완주 매칭의 체크인 가점 회수" 도입 검토.

## 4. 가점을 주지 않는 것 (어뷰징 방지)

- 앱 등록 수 — 자기 앱 양산으로 점수 조작 가능
- 게시글·댓글 — 도배 유인
- 매칭 신청(옵트인) 자체 — 신청 후 방치가 최악의 행동이므로 신청만으로 보상 금지
- 14일 완주 보너스 — v1(+5)에서 제거, 체크인 +1×14 로 대체 (이중 지급 방지)

## 5. 노출·활용

| 위치 | 내용 |
|---|---|
| 전 서비스 닉네임 옆 `★N` | 상시 노출 (게시판·댓글·browse·프로필) |
| `/stats` 신뢰도 랭킹 | **50점 초과자만** TOP 20 (기본값 50 유저·감점자 미노출 — 공개 낙인 방지) |
| 매칭 우선권 (v1.2 예정) | 정원 경쟁 시 신뢰도 높은 순 우선 |
| 크레딧 보상 연동 (예고됨) | `/stats` 배너로 예고. 지급 기준·주기는 별도 설계 (잠금 결정 #3 준수) |

## 6. 이의·복구

- 감점 이의: 관리자가 `trust_score_history` 원장 확인 후 `admin.adjust`로 정정
- 자연 복구: 시간 경과 복구 없음 — 체크인으로만 회복
