# Tester Match 전체 디자인 개편 의뢰 프롬프트

> 사용법: 이 파일 전체를 디자이너(사람 또는 AI 디자인 에이전트)에게 그대로 전달한다.
> 리포에 접근할 수 있는 에이전트라면 리포 루트(`tester-match/`)에서 연 세션에 붙여넣는다. 리포 접근이 없으면 §2~§6 만으로도 작업할 수 있게 썼다.
> 기준: 2026-10-07, 브랜치 `결제심사`. 숫자·정책이 바뀌면 §5 를 먼저 고친 뒤 전달한다.

---

## 1. 무엇을, 왜 맡기는가

당신은 **Tester Match** 웹사이트의 전체 디자인을 새로 잡는 디자이너입니다.

지금 사이트는 개발자가 기능을 붙여 가며 만든 화면이라, 기능은 다 있지만 하나의 브랜드로 읽히지 않습니다. 이번 개편의 목적은 세 가지입니다.

1. **두 사용자의 마음을 움직인다.** 테스터를 구하는 개발자에게는 "부탁이 아니라 투자", 테스트하는 사람에게는 "하루 1분으로 받는 보상"이 한눈에 전해져야 합니다.
2. **믿을 수 있는 서비스로 보인다.** 결제대행사(PG) 심사자, 카드사, Google Play 정책 담당자가 봐도 "회사가 직접 파는 정직한 테스트 서비스"로 읽혀야 합니다. 리워드 앱·앱테크·광고 대행처럼 보이면 심사에서 떨어집니다.
3. **매일 다시 오고 싶은 도구가 된다.** 테스터는 14일 동안 매일 들어와 체크인합니다. 하루 1분이 정말 1분 안에 끝나야 합니다.

운영자는 1인 창업자입니다. 산출물은 개발자(사람 또는 AI)가 바로 코드로 옮길 수 있는 수준이어야 합니다.

## 2. 서비스 한 장 요약

- **문제**: Google Play 는 새 개인 개발자 계정의 앱을 출시하기 전에 **테스터 12명이 14일 동안** 비공개 테스트에 참여할 것을 요구한다. 한국 인디 안드로이드 개발자는 이 12명을 지인·단톡방 부탁으로 구하다 지치고, 테스터는 며칠 뒤 사라진다.
- **무료 기능 (품앗이)**: 개발자끼리 서로의 앱을 테스트해 준다. 앱 등록 → 매칭 목록 → 참여 → 14일 체크인. "맞테스트"는 내 앱을 테스트해 준 사람의 앱을 나도 테스트해 주는 것.
- **유료 기능 (급구 · 유료 테스터)**: 품앗이로 모자란 인원을 회사가 모집·관리하는 커뮤니티 테스터로 채운다. **테스터 1명 1,100원(부가세 포함), 1~30명, 기본 14명(14명이면 15,400원).** 결제하면 매칭 목록 맨 위 "급구" 칸에 표시되고 전 회원에게 알림이 간다. 테스터는 14일 동안 매일 앱을 열고 스크린샷 1장으로 체크인한다. 못 채운 시트·완주하지 못한 시트는 환불된다.
- **테스터 보상**: 유료 시트를 완주한 테스터에게 회사가 크레딧을 지급한다(완주 시 최대 600, 앱이 출시되면 +100, 시트당 최대 700). 크레딧은 5,000부터 기프티콘·네이버페이 포인트로 교환한다. 크레딧은 **구매·양도·현금 환급이 불가능**하다.
- **돈의 흐름 (사이트에 숫자로 공개)**: 회사는 1명 1,100원 가운데 최대 700원을 테스터 보상 비용으로, 나머지 400원을 부가세·카드 수수료·서버·보상 발송·운영비로 쓴다. 남는 돈은 많지 않고, 그마저 서비스를 계속 운영하는 데 다시 쓴다.
- **운영 맥락**: 운영자는 하루 두 번 자신이 운영하는 카카오톡 단톡방·오픈채팅에 "새 테스트 모집"을 알린다. 그래서 첫 방문은 대부분 **휴대폰, 카카오톡 인앱 브라우저**에서 일어난다고 보고 설계한다.

## 3. 사용자와 그들이 느껴야 할 것

| 사용자 | 상황 | 이 사이트에서 느껴야 할 것 | 핵심 행동 |
|---|---|---|---|
| 개발자 (앱 등록자) | 출시를 앞두고 12명이 안 모여 초조함. 부탁하는 게 민망함 | "돈 몇 만 원이 아니라 내 앱에 대한 투자다", "14일이 관리된다" | 앱 등록 → 품앗이 / 급구 신청·결제 → 콘솔에서 매일 증빙 확인 |
| 테스터 | 새 앱을 먼저 써 보는 재미, 커피 한 잔 정도의 소소한 보상 | "부담 없다, 하루 1분이면 된다", "보상이 정직하게 쌓인다" | 매칭 목록에서 참여 → 매일 체크인 → 크레딧 → 기프티콘 교환 |
| 심사자 (PG·카드사) | 로그인 없이 사이트를 훑어봄 | "판매자·상품·가격·환불 기준·사업자 정보가 분명한 정상 서비스" | 상품 설명·결제 화면·약관·환불 정책·푸터 확인 |
| 운영자 (관리자) | 주문·보상·문의를 처리 | 기능 우선, 빠르게 읽히는 표 | 관리자 화면 (디자인 우선순위 낮음) |

**브랜드 문장 (확정)**: "부탁은 투자로, 하루 1분은 보상으로". 개발자 쪽 문장 "테스터는 부탁하는 게 아니라, 내 앱에 투자하는 겁니다", 테스터 쪽 문장 "하루 1분, 출시 전 앱을 먼저 쓰고 커피 한 잔을 모읍니다".

**원하는 인상**: 믿음직한 · 따뜻한 · 정직한(숫자를 숨기지 않는) · 동료 같은(인디 개발자끼리) · 가벼운(매일 1분).
**피해야 할 인상**: 앱테크·리워드 앱(돈 버는 앱) · 도박·복권·이벤트 경품 · 광고 대행·마케팅 대행 · 고수익·부업 · 관공서 같은 딱딱함 · 해외 SaaS 템플릿 그대로.

## 4. 현재 디자인 (출발점)

- 기술: Next.js 15 App Router + React 19(대부분 서버 컴포넌트), **Tailwind CSS v4** — 디자인 토큰은 `03-output/app/src/app/globals.css` 의 `@theme` 블록 하나에 있다. 별도 UI 라이브러리 없음.

- 색: `trust`(파랑 #2563eb 중심 50~900 단계, 주 버튼·링크) · `spark`(코랄 #ff6b5b, 급구·강조) · `mint`(#10b981, 완료·성공) · `amber`(#f59e0b, 경고·안내 상자) · `crimson`(#ef4444, 오류) · `sky`(#0ea5e9) · Tailwind 기본 `neutral`.
- 형태: 흰 배경, `rounded-2xl` 카드 + 얇은 회색 테두리 + 약한 그림자, 섹션마다 3열 카드 그리드. 다크 모드 없음. 로고는 `components/logo.tsx` 의 `LogoMark` + "Tester **Match**" 글자.
- 공통 요소: 헤더(로고·메뉴 11개·알림 종·관리자/크레딧/닉네임 칩·로그아웃), 푸터(사업자 정보·정책 링크·문의), 오른쪽 아래 떠 있는 버튼 3개(공지·문의 메일·카카오 오픈채팅), 랜딩의 앱 가로 흐름 배너.
- 지금 보이는 문제(운영자·개발자 관찰): 헤더 메뉴가 11개라 좁은 데스크톱에서 넘친다 · 모든 섹션이 같은 카드 그리드라 강약이 없다 · 노란(amber) 상자를 경고·안내·법적 고지에 모두 써서 의미가 섞인다 · 이모지(💰 🔥 ✅)가 아이콘 대신 쓰인다 · 결제·보상 화면이 다른 화면과 톤이 다르다 · 빈 상태·로딩·오류 화면이 제각각이다.

## 5. 바꾸면 안 되는 것 (위반 시 결제 심사·정책 위반)

### 5.1 숫자와 사실
- 화면의 숫자는 코드 상수에서 나온다. 시안에 쓸 값: 1,100원(부가세 포함) · 기본 14명 / 1~30명 · 14일 · 12일 이상 출석 시 완주 · 보상 완주 시 최대 600 + 출시 100 = 최대 700 · 교환 5,000 크레딧부터, 5,000 단위, 1회 최대 50,000 · 충원 기간 결제 후 7일 · 급구 표시 결제 후 14일.
- **문구는 바꿔도 되지만 의미는 바꾸지 않는다.** 결제·환불·약관·개인정보·크레딧 정책 문구는 운영자 승인 없이 바뀔 수 없다. 더 좋은 표현이 있으면 시안과 별도로 "문구 제안" 목록으로 낸다(원문 / 제안 / 이유).

### 5.2 반드시 보여야 하는 것
- **모든 페이지 하단(결제 페이지 포함)에 사업자 정보**: 상호(낰낰컴퍼니), 대표자, 사업자등록번호, 사업장 주소, 전화(유선 번호), 이메일, 그리고 나중에 들어갈 통신판매업 신고번호 자리. 작아도 되지만 읽혀야 한다.
- 급구(유료 테스터) 페이지: 상품 설명 · 가격(부가세 포함) · 진행 방식 · 환불 기준 표 · 돈의 쓰임(보상 700 / 운영 400 막대) · 판매·환불 주체가 회사라는 문장 · 약관·환불 정책 링크. **로그인하지 않아도 전부 보인다.**
- 결제 오픈 전 상태 표시("결제 오픈 대기" 배지, 결제 버튼 자리의 안내). 오픈 뒤에는 사라질 요소로 설계한다.
- 크레딧 화면·보상 화면의 규칙 4줄(보상으로만 적립 · 구매 불가 · 양도 불가 · 현금 환급 불가).

### 5.3 쓰면 안 되는 표현·이미지
- 크레딧 맥락의 "구매·충전·환전·현금·환급"(부정문 "~할 수 없습니다"는 허용). 크레딧을 돈처럼 보이게 하는 시각(₩ 기호를 크레딧에 붙이기, 동전 더미, 지폐, 돈다발, 금고, 잭팟·슬롯머신, 상자 열기).
- "리뷰·별점·평점"을 보상과 연결하는 모든 표현과 그림(별 다섯 개 + 보상, 리뷰 쓰면 적립 등). Google Play 리뷰 인센티브 금지 정책이다. 서로 테스트해 주는 기능 이름은 "맞테스트"다.
- "광고·마케팅·노출 보장·설치 수 보장·수익 보장·순위 상승". 급구는 "테스터 모집에 포함된 상단 표시"이지 광고 상품이 아니다.
- "중개·판매자/구매자 매칭 수수료". 회사가 테스터를 모집·관리하고 직접 판다.
- 테스터에게 "돈을 번다"는 표현. "보상을 받는다", "커피 한 잔을 모은다"로 쓴다.

### 5.4 접근성·환경
- WCAG 2.2 AA: 본문 대비 4.5:1, 큰 글자 3:1, 터치 영역 44×44px 이상, 키보드 포커스 표시, 색만으로 의미를 전하지 않기(상태 배지는 글자 포함).
- 기준 폭 **375px**(가로 스크롤 금지)과 1280px. 카카오톡 인앱 브라우저에서 고정 하단 요소가 주소창·키보드에 가리지 않게.
- 한글 조판: `word-break: keep-all`, 본문 줄 간격 1.6 안팎, 숫자는 고정폭.
- 무거운 애니메이션 라이브러리·대형 이미지 금지. 움직임은 `prefers-reduced-motion` 을 존중한다.

## 7. 산출물

**단계 1 — 방향 제안 (먼저 이것만 내고 운영자의 선택을 기다린다)**
- 서로 다른 방향 2~3안. 각 안마다: 한 줄 콘셉트 · 무드 키워드 3개 · 색 팔레트(주색·보조·강조·의미색) · 글꼴 조합 · 랜딩 첫 화면(히어로) 모바일·데스크톱 시안 1장씩 · 이 안이 §3 의 "피해야 할 인상"을 어떻게 피하는지 2줄.
- 기존 trust 파랑·spark 코랄을 유지·진화하는 안을 최소 하나 포함한다(전환 비용이 가장 낮다).

**단계 2 — 선택된 방향으로 상세화**
1. **디자인 토큰** — Tailwind v4 `@theme` 블록에 바로 붙일 수 있는 형태. 의미 이름 기준(예: `--color-brand-*`, `--color-accent-*`, `--color-success-*`, `--color-warning-*`, `--color-danger-*`, `--color-surface-*`, `--color-ink-*`), 글자 크기·줄 간격 단계, 반경, 그림자, 간격. 기존 토큰 → 새 토큰 대응표.
2. **컴포넌트 명세** (상태별: 기본·hover·focus·disabled·loading·error) — 버튼 3종 · 배지(BOOST/급구, 결제 오픈 대기, 주문·매칭 상태, 신뢰도 ★) · 앱 카드(유료 시트 표시 포함) · 숫자 타일 · 돈의 쓰임 막대(보상 700 / 운영 400) · 안내 상자 3종(정보 / 주의 / 법적 고지 — 지금처럼 하나로 섞지 않기) · 폼 요소 · 동의 체크 목록 · 표(환불 기준) · 빈 상태 · 토스트 · 헤더·모바일 내비 · 푸터 · 떠 있는 버튼.
3. **페이지 시안** — P0 전부, P1 의 `/browse`, `/my-tests`(체크인), `/apps/[id]`, `/credits`. 각 375px·1280px. 비로그인·로그인·빈 상태 중 의미 있는 것.
4. **아이콘·일러스트 방향** — 이모지를 대체할 아이콘 세트(라이선스 명시), 일러스트를 쓴다면 §5.3 을 지키는 소재.
5. **문구 제안** (선택) — §5.1 규칙대로 원문/제안/이유 표.
6. **구현 메모** — 개발자가 옮길 때 알아야 할 것: 새로 필요한 컴포넌트, 기존 컴포넌트(`components/*.tsx`)와의 대응, 바꿔야 하는 전역 스타일, 다크 모드 여부와 비용.

형식: 이미지 시안(Figma 링크 또는 PNG) + 토큰·명세는 마크다운. 리포 접근이 있는 에이전트라면 `03-output/design/` 아래에 마크다운과 이미지로 남기고, **코드는 고치지 않는다**(구현은 별도 작업으로 맡긴다).

## 8. 진행 방식

1. 시작 전에 꼭 필요한 질문만 최대 5개 묻는다. 답이 없어도 진행할 수 있는 것은 가정을 적고 진행한다.
2. 단계 1(방향 2~3안)을 내고 멈춘다. 운영자가 고르거나 섞으라고 하면 단계 2로 간다.
3. 단계 2 중간에 P0 랜딩·급구 신청 두 장을 먼저 보여 주고 확인받은 뒤 나머지를 진행한다.
4. 리포 접근이 있으면 실제 화면을 직접 본다: 로컬 개발 서버(`05-harness/scripts/tm-dev local` 후 `pnpm -C 03-output/app dev`)를 쓰고 운영 사이트에는 아무것도 제출하지 않는다. 결제 버튼은 누르지 않는다.
5. 배포·마이그레이션·결제·메일 발송·외부 서비스 설정 변경은 하지 않는다.
