# 2026-10-04 — 로컬 스모크 테스트가 운영 페널티 스윕을 실행한 사고

- 발생: 2026-10-04 21:57 KST (12:57 UTC) · 발견: 즉시 (응답 코드 200)
- 작업: Azure 이전 1-2단계 (`feat/azure-hosting`) — Node standalone 빌드 로컬 스모크 테스트
- 결정: **유지** (사용자 선택, 되돌리지 않음)

## 무슨 일이 있었나

standalone 서버를 `.env.local`(운영 Supabase·실메일 키)로 띄우고 GET 위주 스모크를 하던 중, "크론이 무인증이면 401 인가" 를 보려고 `POST /api/cron/penalty-sweep` 을 호출했다. `.env.local` 에는 `CRON_SECRET` 이 없고, `verifyCronAuth` 는 비밀이 없으면 통과시키는 구조여서 운영 DB 에 대해 페널티 스윕이 1회 실행됐다.

## 영향 (운영 DB 읽기 전용 집계)

| 항목 | 값 |
|---|---|
| 이탈 처리된 매칭 | 5건 — 전부 무료 품앗이 (유료 시트 0) |
| 신뢰도 | `penalty.no_checkin` −10 × 5 = −50 |
| 사이트 알림 | `match_penalized` 5건 (메일 발송 없음 — 스윕 라우트에 메일 경로 없음) |
| 크레딧 원장 | 변화 없음 |
| 판정 내용 | 4건: 참여 5일째, 체크인 0회 / 1건: 1일차 체크인 후 6일째 미체크인 |

정책상 스윕 예정 시각은 매일 KST 21:00 이고 이번 실행은 그 57분 뒤였다. 판정 기준(마지막 체크인 후 5일, 24시간 단위 일차)상 같은 날 정규 스윕도 같은 판정을 내릴 대상이다. 다만 GitHub 스케줄 지연(3~14시간) 동안 남아 있었을 체크인 기회를 몇 시간 앞당겨 닫았다.

## 원인

1. 로컬 서버(어떤 형태든)는 운영 DB 를 가리킨다는 사실을 알고 있었고 메모에도 "로컬에서 리마인더·페널티 크론 호출 금지" 가 있었으나, "인증 확인용 요청은 괜찮다" 고 잘못 판단했다.
2. `verifyCronAuth` 가 **비밀이 없으면 통과** (fail open). 운영에 비밀이 빠지는 실수가 생겨도 크론이 인터넷에 열린다.

## 조치

- `feat/azure-hosting`: `verifyCronAuth` 를 **기본 거부(fail closed)** 로 변경 — 비밀이 없으면 테스트 러너(`NODE_ENV=test`) 또는 `CRON_ALLOW_UNAUTHENTICATED=1` 명시 때만 통과. 단위 테스트 3건 추가. Azure 에서 `CRON_SECRET` 앱 설정이 빠져도 크론은 닫힌다.
- 작업 규칙: 로컬 서버의 `/api/cron/*` 에는 어떤 요청도 보내지 않는다 (인증 확인 포함). 크론 인증은 단위 테스트로만 확인한다.
- 되돌리지 않음 (사용자 결정): 정책 시각 기준 판정과 동일, 돈·유료 시트 무관.
