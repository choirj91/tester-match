# ADR-0019: 친구 추천 → 신뢰도 보너스 (크레딧 없음)

- **상태**: Proposed (2026-10-07 운영자 결정 — 화면 검토 뒤 배포 시 Accepted)
- **결정자**: nakjun
- **관련**: ADR-0010 (신뢰도 정책 — 본 문서가 "가점은 체크인에만" 원칙에 예외 하나를 더한다), ADR-0014 (크레딧 적립원 단일화), ADR-0017 (크레딧 보상 전용·PG 심사 표현 규칙)
- **개정**: ADR-0010 Decision 의 "체크인 실행에만 가점"

## Context

- 신뢰도(★)는 체크인 +1, 옵트아웃 −3, 무단 이탈 −10 으로만 움직인다(ADR-0010). 이탈 감점을 받은 회원이 점수를 되찾는 길은 체크인을 다시 쌓는 것뿐이다.
- 운영자 의도(2026-10-07): 감점된 회원이 실제로 테스트하는 사람을 데려오면 점수를 회복할 수 있게 한다. 데려온 사람도 같은 만큼 받는다.
- 크레딧은 유료 시트 완주 보상으로만 적립된다(ADR-0014). 크레딧은 기프티콘·네이버페이 포인트로 교환되므로(ADR-0017) 현금성 부채다.
- 가입만으로 보너스를 주면 부계정으로 쉽게 부풀릴 수 있다. 가입은 Google 계정 하나면 된다.

## Decision

1. **조건**: 회원이 자기 추천 링크(`/r/{회원 id}`)를 공유한다. 그 링크로 들어온 사람이 새로 가입하고, 그 사람의 **첫 유료 테스터 시트 보상이 확정(released)** 되면 추천인과 피추천인 **모두 신뢰도 +10** (`REFERRAL_TRUST_DELTA`). 피추천인 1명당 1회.
2. **크레딧은 주지 않는다.** 이 기능은 `credits_ledger` 를 건드리지 않는다. 화면·알림 문구에 크레딧·기프티콘·포인트·현금·보상금을 쓰지 않는다.
3. **연결 방식**: 링크는 방문자에게 추천 쿠키 `__Host-tm_ref`(30일, HttpOnly·Secure·SameSite=Lax·Path=/)를 남긴다. `__Host-` 접두사라 같은 상위 도메인의 다른 서브도메인이 추천인을 바꿔 쓸 수 없다. 여러 링크를 열면 마지막 링크가 이긴다. 링크는 로그인 여부를 확인하지 않는다(인증 서버 호출 없음) — 가입(Google 로그인 콜백, 이메일 가입 확인) 직후 회원 행이 24시간 안에 만들어진 새 회원이고 아직 추천 기록이 없을 때만 추천 관계를 기록하므로 기존 회원의 쿠키는 기록되지 않는다. 자기 자신, 탈퇴·정지 회원은 추천인이 될 수 없다. 로그인 경로에서 추천 기록은 2초까지만 기다린다 — 넘기거나 일시 오류면 쿠키를 남겨 다음 로그인에서 다시 시도하고, 로그인은 그대로 끝난다.
4. **후보 선정과 지급 판정은 DB 가 한다**: 6시간 보상 크론(`seat-reward-release`)은 DB 함수 `referral_reward_candidates(n)` 으로 후보(대기 추천 중 피추천인에게 확정 시트가 있는 것, id 순, 1~50건 — 크론은 5건)를 받아 DB 함수 `grant_referral_reward(추천 id)` 를 부르기만 한다. 유료 시트를 하지 않는 피추천인(이메일 가입자는 유료 시트를 할 수 없다)이 아무리 쌓여도 후보 조건이 DB 에서 걸리므로 뒤에 생긴 추천을 가리지 않는다. 함수는 추천 행과 두 회원 행을 잠근 뒤 피추천인의 **첫** 확정 유료 시트(확정 시각, id 순)를 근거로 아래 순서로 판정한다.

   | 판정 | 조건 | 결과 |
   |---|---|---|
   | 무효 `self_purchase` | 그 시트의 주문을 추천인이나 피추천인 본인이 결제 | 점수 없음 |
   | 무효 `inactive` | 추천인·피추천인 중 탈퇴·정지(`status` 가 active 아님 또는 `deleted_at`) | 점수 없음 |
   | 무효 `referrer_cap` | 추천인이 최근 90일에 이미 5건 지급받음 | 점수 없음 |
   | 지급 | 그 밖 | 양쪽 +10 (0~1,000), `trust_score_history` reason `reward.referral` |

   - **무효는 최종 상태**다(`voided_at`, `void_reason`). 다시 심사하지 않고 대기 목록에서 빠진다. 지급과 무효 중 하나로만 끝난다(DB 제약).
   - 증감(+10)과 상한(90일 5건)은 함수 안 상수다. 서버는 증감 값을 넘기지 않는다 — 화면 문구용 TS 상수는 테스트가 SQL 과 같은지 확인한다.
   - 확정 시트가 아직 없으면(`pending`) 아무것도 바꾸지 않는다. 이미 끝난 추천은 `already`. 한 트랜잭션이라 다시 실행해도 두 번 지급되지 않는다.
5. **공개 추천 랭킹**: `/stats` 에 지급까지 간 추천 수 기준 TOP 20 을 보인다. 가입만 한 추천, 무효가 된 추천은 세지 않는다.

## Why

- **크레딧 대신 신뢰도**: "친구 초대 → 기프티콘"은 PG 심사자에게 리워드·앱테크 사업으로 읽힌다(ADR-0017 의 업종 판정 위험). ADR-0014·0017 은 크레딧을 유료 시트 보상 하나로 묶어 두었다. 신뢰도는 돈으로 바꿀 수 없는 표시라 이 두 원칙을 건드리지 않는다.
- **완주한 유료 시트를 조건으로**: 유료 시트 확정에는 14일 중 12일 이상 스크린샷 체크인과 구매자 확인(또는 3일 무응답)이 필요하다. 부계정으로 +10 을 얻으려면 그 계정으로 2주 가까이 실제 테스트를 해야 하므로 부풀리는 비용이 얻는 점수보다 크다.
- **+10**: 무단 이탈 감점(−10) 한 번을 되돌리는 크기다. 체크인 10일 분량이라 체크인보다 쉬운 지름길이 되지 않는다.
- **자기 결제 무효**: 추천인이 직접 유료 테스터를 결제하고 부계정(피추천인)을 그 시트에 넣으면 1,100원으로 양쪽 +10 을 살 수 있다. 첫 확정 시트의 결제자가 둘 중 하나면 무효로 끝내 이 경로를 막는다. 첫 시트로만 판단하므로 무효가 된 피추천인은 나중 시트로 다시 받을 수 없다.
- **90일 5건 상한**: 제3자 결제 시트로 부계정을 여러 개 완주시키는 경우를 잡지 못하므로 추천인 한 명이 얻는 점수를 90일 +50 으로 묶는다. 상한에 걸린 추천도 최종 무효다 — 피추천인 몫도 함께 없어진다(대기로 남겨 두면 90일 뒤 한꺼번에 지급되는 우회가 된다).
- **판정을 DB 에**: 판정에 쓰는 값(시트 결제자, 회원 상태, 추천인 지급 수)을 잠근 상태에서 한 번에 읽어야 겹친 크론 실행이 상한을 함께 넘거나 탈퇴 직후에 지급하지 않는다. 서버가 넘기는 값(시트 id, 증감)을 믿지 않는다.
- **`__Host-` 쿠키**: 가입 확인 쿠키(`CONFIRM_COOKIE`)와 같은 처리다. 서브도메인이 상위 도메인 쿠키를 심어 남의 가입을 자기 추천으로 돌리는 것을 막는다.
- **랭킹은 완주 기준**: 가입 수는 공짜로 만들 수 있어 공개 순위에 쓰면 부계정 경쟁이 된다.

## Consequences

- (+) 감점 회원의 회복 경로가 생기고, 유료 시트를 끝까지 하는 테스터가 늘어난다.
- (+) 지급은 DB 함수 하나·원장 기록 — 감사 가능, 멱등.
- (−) 신뢰도 가점 경로가 체크인 밖으로 하나 늘어난다. ADR-0010 의 상한(1,000)·하한(0)은 그대로 적용된다.
- (−) 이메일 가입은 인증 메일을 링크를 연 브라우저와 다른 기기에서 열면 추천 쿠키가 없어 연결되지 않는다. 사후 수동 연결 수단은 없다.
- (−) 쿠키는 마지막으로 연 링크 기준이다. 여러 링크를 열면 마지막 추천인만 기록된다.
- (−) 무효는 되돌리지 않는다. 운영자가 잘못된 무효를 바로잡을 화면은 없다 — 필요하면 `admin.adjust` 로 개별 조정한다.
- 테이블 `referrals`(지급·무효 열 포함), 함수 `grant_referral_reward(bigint) returns text`·`referral_reward_candidates(integer) returns setof bigint`, 알림 유형 `referral_reward` (마이그레이션 `20261007000002`, 다시 실행해도 안전). 신뢰도 정책 문서(`03-output/policy/trust-score.md`)는 운영자 승인 뒤 갱신한다.
