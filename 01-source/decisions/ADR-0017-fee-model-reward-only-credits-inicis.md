# ADR-0017: 유료 테스터 단가 1,100원·운영비 모델·크레딧 보상 전용화·PG KG이니시스

- **상태**: Proposed (2026-10-06 운영자 결정 반영 — 정책 문구 승인 시 Accepted)
- **결정자**: nakjun
- **관련**: ADR-0003 (크레딧 모델 — 본 문서가 단가·충전·외부 전환 조항을 개정), ADR-0011·ADR-0012 (유료 테스터), ADR-0014 (마일스톤 보상 — 상한 700 유지), ADR-0016 (포트원 — PG 를 KG이니시스로 변경)
- **대체**: ADR-0003 Decision 의 "매칭 1건 비용 1,000 크레딧", "충전 단위", "외부 전환(v3) 호환"; ADR-0016 Decision 1 의 "PG 는 NHN KCP", Decision 7 의 "구매자 정보는 닉네임·이메일만"

## Context

- 2026-10-05 포트원 경유 NHN KCP 전자결제 계약이 반려됐다. 포트원의 위험 업종 안내와 대조하면, 사이트에 보이던 "크레딧 충전(ADR-0003 계획)", "외부 포인트 전환(v3)", "보유 크레딧으로 결제", "기프티콘 교환" 표현이 **포인트충전·상품권/기프티콘** 업종(KCP 입점불가)으로 읽힐 여지가 컸다. "매칭 플랫폼"이라는 설명은 **중개 서비스**(2차 정산)로도 읽힌다.
- KG이니시스는 포인트·환금성 업종을 "심사 후 가능"으로 두되 **환급·포인트 현금화 불가, 인증 강화, 카드사 기준 금액 제한**을 조건으로 한다. 중개 서비스는 심사 가능 목록에 없다.
- 포트원 "서비스 필수 구축 요건": 실도메인, 사업자 정보 5항목(전화는 유선번호) 전 페이지 하단 고정, 비실물 서비스 상세 설명, 환불 정보, 이용약관, 개인정보취급방침.
- 유료 테스터 주문 페이지가 비관리자에게 "곧 오픈합니다"로 가려져 있어 심사자에게는 상품이 없는 사이트로 보인다.
- 운영자 결정(2026-10-06): 결제 페이지를 숨기지 않고 "오픈 대기"로 공개, 1명당 1,100원(수수료 성격), 크레딧 구매·교환 불가 + 보상 교환 페이지(네이버페이 포인트·기프티콘), 결제 페이지에 "운영비용만 사용" 메시지.

## Decision

1. **단가**: 테스터 시트 1명 = **1,100원(부가세 포함)**. 1원 = 1 크레딧은 유지한다. 보상으로 적립한 크레딧으로 시트를 열 때도 1,100 크레딧이다.
2. **수익 모델 표현**: "결제 금액은 14일을 완주한 테스터의 보상과, 그 사이에 드는 결제 수수료·운영비용에 쓰인다." 수익 극대화가 아니라 테스터가 보상을 받고 개발자가 요건을 채우도록 잇는 서비스로 설명한다. 보상 상한은 ADR-0014 의 **시트당 700 크레딧을 유지**한다. 1,000 으로 올리는 안(보상 1,000 + 운영 100)은 보류 — 운영자가 택하면 ADR-0014 를 갱신한다.
3. **크레딧은 보상 전용**: (1) 구매할 수 없다 — 어떤 결제수단으로도 적립되지 않고, 유료 테스터 결제 금액은 크레딧으로 전환되지 않는다. (2) 타인에게 양도·판매·교환할 수 없다. (3) 현금으로 환급되지 않는다. ADR-0003 의 충전 단위·외부 포인트 전환(v3) 조항은 폐기한다.
4. **보상 교환 상점**: 크레딧은 **기프티콘** 또는 **네이버페이 포인트(쿠폰)** 로만 바꾼다. 5,000 크레딧 단위, 1회 최대 50,000, 본인 휴대폰 번호, 한 번호는 한 계정, 영업일 3일 처리, 신청 시 차감·거절 시 복구 — ADR-0012 의 기프티콘 규칙을 그대로 쓰고 종류만 늘린다. 네이버페이 포인트는 제휴 API 없이 운영자가 쿠폰(충전 코드)을 사서 수동 지급한다.
5. **결제 페이지 공개(오픈 대기)**: `/paid-testers` 는 비로그인에게도 상품·가격·진행 방식·환불 기준·운영비 메시지를 보여 주고, 로그인 회원에게 주문 폼을 보여 준다. 결제 버튼은 실연동 채널 전환 전까지 관리자·허용목록(심사) 계정만 동작하고, 그 외에는 "결제 오픈 준비 중" 안내를 보인다. 서버 주문 API 의 게이트(`canOrderPaidTesters`)는 그대로다.
6. **PG**: KG이니시스(포트원 V2). 결제창에 구매자 이름(닉네임)·이메일·**휴대폰 번호**를 넘긴다. 휴대폰 번호는 결제 화면에서 입력받아 PG 에만 전달하고 **회사 서버·DB 에 저장하지 않는다**. NHN KCP 전용 `bypass` 는 제거한다. 채널 키는 환경변수 교체만으로 바꾼다.
7. **사이트 표현 규칙**: 크레딧 맥락에서 "구매·충전·환전·현금·환급" 을 쓰지 않는다. "보상·보상 교환·복구(되돌림)" 를 쓴다. "중개·판매자/구매자 매칭 수수료" 대신 "회사가 모집·관리하는 테스터", "회사가 직접 판매·직접 환불", "테스터에게 현금을 지급하지 않음" 으로 쓴다.

## Why

- **업종 판정**: 카드로 살 수 있는 것은 회사가 직접 파는 비실물 서비스(테스터 시트)뿐이고, 크레딧은 결제와 연결되지 않는 보상이면 포인트충전·상품권 판매가 아니다. 테스터에게 현금 정산이 없으면 중개(2차 정산)도 아니다. 이니시스의 조건(환급·현금화 불가)을 정책 문구로 그대로 만족한다.
- **1,100원**: 1,000원 + 부가세 100원으로 읽혀 "수수료·실비" 성격이 드러난다. 운영자가 요구한 "수수료 느낌"을 가격 자체로 표현한다.
- **보상 상한 700 유지**: 보상 산정 로직(`lib/seat-reward-rules.ts`)·약관·가이드 수치 변경 없이 심사 대응을 먼저 끝낸다. "운영비용만" 메시지는 "보상 + 결제 수수료·운영비용" 으로 써서 700 에서도 거짓이 되지 않게 한다.
- **공개 + 게이트**: 심사자는 로그인 없이 상품·가격·사업자 정보를 보고, 심사 계정으로 결제창까지 간다. 일반 회원은 테스트 채널로 결제하는 사고가 없다.
- **휴대폰 미저장**: 이니시스가 요구하는 값은 결제창에만 필요하다. 저장하면 개인정보 항목이 늘고 유출 면적이 넓어진다.

## Consequences

- CLAUDE.md 잠금 결정 3 을 갱신한다 (본 문서가 근거).
- 코드: `PAID_TESTER_PRICE_KRW = 1100`, `credit_redemptions.kind` 에 `naver_points` 추가(마이그레이션 `20261006000001`), 보상 교환 상점 `/rewards`, 결제 화면 휴대폰 입력, KCP bypass 제거.
- 정책 4종(약관·개인정보·환불·크레딧) 개정 — **운영자 승인 뒤 시행**. 약관 제3조·환불 정책 제6조에 따라 시행 7일 전 공지(시행일 2026-10-13).
- 과거 1,000원 테스트 주문(13·14·15)은 그대로 둔다. `amount_krw` 는 주문 시점 단가로 기록되므로 단가가 섞여도 정산은 주문 행 기준이다.
- 네이버페이 포인트 지급은 수동이다. 신청이 늘면 제휴 또는 자동화를 검토한다.
