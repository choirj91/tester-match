# ADR-0010: 신뢰도(Trust Score) 정책 — 체크인 중심 증감 규칙

- **날짜**: 2026-07-24 (v1 완주 +5 채택 → 당일 v1.1 개정: 체크인 +1, 상한 1,000)
- **상태**: 채택 (v1.1)
- **관련**: ADR-0003 (크레딧 모델), BP §핵심 차별화 "Trust Score"

## Context

`users.trust_score`(시작 50, 0~100)와 `trust_score_history` 원장은 스키마부터 존재했고
UI 전면(★N)에 노출 중이었으나, 증감 규칙은 **감점(무단 이탈 −10)만 구현**되어 있었다.
가점 경로가 없어 전 사용자가 50 이하로만 수렴 — 점수가 "성실함의 신호"가 아니라
"사고 이력 유무"만 표시했다. 공개 랭킹 페이지(`/stats`) 오픈과 크레딧 보상 예고로
점수의 의미를 확정할 필요가 생겼다.

## Decision

**체크인 실행에만 가점, 이탈에만 감점** 원칙 (v1.1):

| 이벤트 | 증감 |
|---|---|
| 일일 체크인 1회 | +1 (UNIQUE(match_id, day_n) 가드 — 하루 1회) |
| 자진 옵트아웃 | −3 (버튼에 사전 고지) |
| 무단 이탈 | −10 (기존 유지) |

상한 100 → **1,000** (DB CHECK 제약 변경, 마이그레이션 20260724000001).
v1의 완주 보너스(+5)는 체크인 +1×14 로 대체 — 이중 지급 방지 위해 제거.
앱 등록·게시글·옵트인 등 어뷰징 가능한 행위에는 점수를 연결하지 않는다.
공개 랭킹은 50점 초과자만 노출한다 (감점자 공개 낙인 방지).
상세 수치·근거: [03-output/policy/trust-score.md](../../03-output/policy/trust-score.md)

## Why

- 행동(체크인)과 보상의 즉시 연결 — 완주까지 기다리지 않아 동기 부여가 매일 발생
- 상한 1,000: 만점까지 체크인 950회 ≈ 완주 68회 분량 — 장기 순위 경쟁 여지
- 옵트아웃(−3) < 무단 이탈(−10): 포기해도 알리고 나가는 것이 항상 유리 — 개발자 정원 즉시 복구 실익
- 알려진 트레이드오프: 부분 체크인 후 이탈 시 순이익 가능 (13일 체크인 +13 − 10 = +3). 파밍 패턴 관측 시 페널티 상향 또는 가점 회수 검토 (정책 문서 §3)

## Consequences

- (+) 점수가 상승 가능해져 랭킹·매칭 우선권·크레딧 보상의 기반 지표로 사용 가능
- (+) 모든 증감이 `lib/trust.ts` 단일 함수 + history 원장 경유 — 감사 가능
- (−) 기존 완주자 소급 가점 없음 (시행일 이후부터) — 문의 시 admin.adjust 로 개별 판단
- (−) 옵트아웃 감점 신설 — UI 고지 문구 유지 필수, 무고지 감점은 CS 리스크
