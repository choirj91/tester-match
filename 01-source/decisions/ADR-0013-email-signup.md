# ADR-0013: 이메일 회원가입 추가 (Google 전용 로그인 개정)

- **상태**: Accepted (2026-10-03)
- **결정자**: nakjun
- **관련**: ADR-0004 (인증 전략 — Google 전용에서 개정), ADR-0012 (유료 시트)

## Context

- 결제대행사 가맹점 심사는 "상품 구매가 가능한 ID/비밀번호 테스트 계정"을 요구한다. Google 로그인만으로는 제공할 수 없다.
- 앱 등록자(구매자)에게 Google 계정을 강제할 이유는 없다. 반면 테스터는 Play 스토어·테스터 그룹 때문에 어차피 Google 계정이 필요하다.
- 운영 커뮤니티는 카카오톡 오픈채팅이라, 채팅방의 누가 어느 회원인지 연결할 식별자가 필요했다.

## Decision

1. **이메일·비밀번호 회원가입을 추가**한다. 가입 시 닉네임과 **카카오톡 닉네임**(오픈채팅 이름)을 필수로 받는다. Google 가입 회원은 프로필에서 선택 입력.
2. **이메일 인증 필수.** 서버가 인증 링크를 생성해 서비스 메일로 발송하고, 인증 전에는 로그인할 수 없다. 발송 실패 시 미인증 계정을 삭제해 재시도 가능하게 한다.
3. **유료 시트 참여는 Google 인증 계정만** 허용한다 (`PAID_SEAT_REQUIRES_GOOGLE`). 이메일 가입으로 계정을 쉽게 늘려 보상을 쌓는 경로를 막는다. 앱 등록·시트 구매는 이메일 계정도 가능.
4. 카카오톡 닉네임은 **공개 페이지에 노출하지 않는다** (운영자 식별·안내용).
5. 가입 화면은 인증 메일 발신 도메인이 검증될 때까지 닫아둔다 (`NEXT_PUBLIC_EMAIL_SIGNUP_ENABLED`). 이메일 **로그인** 폼은 즉시 제공한다 (심사 계정 등 운영자가 만든 계정용).
6. 공개 전 주문은 관리자 + 허용목록(`PAID_TESTERS_ORDER_ALLOWLIST`) 계정만 가능하며, 허용목록 계정의 주문은 **심사 모드**(시트 미개방, 급구·전 회원 알림 없음)로 처리한다.

## Consequences

- 인증 메일 발송에는 검증된 발신 도메인이 필요하다 (Resend 도메인 검증 — 선결 과제).
- 가입 엔드포인트는 임의 주소로 메일을 보내게 되므로, 가입을 열기 전에 봇 방지(Turnstile 등)가 필요하다.
- Supabase 의 이메일 가입 API 자체는 열려 있어, 우리 화면을 거치지 않은 가입은 카카오톡 닉네임 없이 생성될 수 있다 (공개 가입 차단은 Google 신규 가입까지 막으므로 보류).
- 비밀번호 재설정 흐름은 후속 과제.
- 개인정보처리방침 수집 항목에 비밀번호·카카오톡 닉네임을 추가했다.
