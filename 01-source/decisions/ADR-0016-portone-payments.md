# ADR-0016: 결제 연동을 포트원(PortOne) 경유 NHN KCP 로 전환

- **상태**: Accepted (2026-10-05)
- **결정자**: nakjun
- **관련**: ADR-0011 (유료 운영자 테스터), ADR-0012 (커뮤니티 테스터 마켓), ADR-0003 (1매칭 = 1,000원), ADR-0007 (결제 v2 보류 — ADR-0011 이 해제)
- **대체**: ADR-0011·ADR-0012 의 "토스페이먼츠 결제위젯" 연동 조항. 가격·환불 기준·크레딧 모델은 그대로다.

## Context

- 토스페이먼츠와 직접 계약해 결제위젯을 붙였고(샌드박스), 2026-10-04 전자결제 심사도 통과했다. 그러나 가입비가 현 단계 매출 규모에 비해 부담스러워 운영자가 계약을 진행하지 않기로 했다.
- 포트원은 PG 가 아니라 여러 PG 를 한 가지 방식으로 붙여 주는 연동 창구다. 포트원을 통해 NHN KCP·KG이니시스에 전자결제를 신청했다.
- PG 마다 결제창에 넘겨야 하는 구매자 정보가 다르다. KG이니시스는 PC 결제에 구매자 이름·휴대폰 번호·이메일이 필수인데, 우리는 회원의 휴대폰 번호를 수집하지 않는다. NHN KCP 는 필수 구매자 정보가 없다.

## Decision

1. 결제는 **포트원 V2** 로 연동하고, PG 는 **NHN KCP**, 결제 수단은 **신용·체크카드** 하나로 시작한다.
2. 포트원 결제 ID 로 **우리 주문 코드**를 그대로 쓴다. 포트원은 같은 결제 ID 로 두 번 결제 성공하는 것을 막으므로 주문당 결제는 한 번뿐이다.
3. 포트원에는 서버 승인 단계가 없다(PG 승인이 결제창 안에서 끝난다). 서버는 **결제를 조회해 상태(PAID)와 금액을 주문과 대조**한 뒤에만 주문을 확정한다. 입력은 주문 코드 하나이고, 결제 여부와 금액은 포트원 조회 결과에서만 읽는다.
4. 조회 실패는 "결제 없음"으로 읽지 않는다. 확인할 수 없으면 주문을 확정하지도 취소하지도 않는다.
5. 취소된 주문에 결제가 들어와 있거나 결제 금액이 주문과 다르면 주문을 확정하지 않고 "확인 필요" 메모를 남겨 일일 리포트에 올린다. 관리자가 결제 대기 주문을 취소할 때는 먼저 결제 여부를 조회한다.
6. 환불은 당분간 수동이다(PG 관리자에서 취소 → 관리자 화면에 반영). 포트원 취소 API 로 자동화하는 것은 다음 단계로 둔다.
7. 구매자 정보는 지금 가진 것(닉네임·이메일)만 결제창에 넘긴다. 결제를 위해 새 개인정보를 수집하지 않는다.

## Why

- **비용**: 직접 계약의 가입비를 피한다. PG 별 가입비·연관리비·수수료는 계약 단계에서 확정한다.
- **교체 가능성**: 포트원 뒤의 PG 는 채널 키만 바꿔 교체하거나 추가할 수 있다. KG이니시스 심사가 먼저 끝나더라도 코드 변경 없이는 못 쓰지만(구매자 휴대폰 번호 필요), 그때 필요한 변경은 결제 화면 입력칸과 개인정보처리방침에 한정된다.
- **개인정보 최소 수집**: NHN KCP 를 고른 이유. KG이니시스는 휴대폰 번호 수집을 강제한다.
- **조회 기반 확정**: 토스의 "서버가 승인을 요청해야 과금" 구조가 없으므로, 서버가 과금을 막는 문이 없다. 대신 주문 확정을 조회 결과에만 의존하게 해 위·변조와 중복 반영을 막는다.

## Consequences

- 토스 연동 코드(`lib/toss.ts`, 결제위젯)는 제거한다. `payments.provider` 에 `portone` 을 추가한다(기존 `toss` 행은 샌드박스 기록으로 남는다).
- 서버가 과금을 막을 수 없으므로 "주문은 취소됐는데 결제는 된" 경우가 이론상 생긴다. 성공 화면 확인, 미결제 주문 스윕의 결제 조회, 관리자 취소 전 조회로 잡는다. 스윕이 취소한 주문에 구매자가 뒤늦게 결제하고 성공 화면으로 돌아오지 않는 경우는 잡지 못한다 — 포트원 웹훅 연동으로 보완한다(후속).
- 금액 위·변조는 조회 대조로 걸러 내지만 결제 자체는 일어난다. 포트원 결제 정보 사전 등록(금액 고정)으로 결제 단계에서 막을 수 있다(후속).
- 환불정책·개인정보처리방침의 "토스페이먼츠" 표기를 포트원·NHN KCP 로 바꿔야 한다(운영자 승인 사항).
- 빌드 시 `NEXT_PUBLIC_PORTONE_STORE_ID`·`NEXT_PUBLIC_PORTONE_CHANNEL_KEY`, 서버 시크릿 `PORTONE_API_SECRET` 이 필요하다. 테스트 채널과 실연동 채널은 채널 키로 구분된다.
- 카드 PG 심사가 끝나 실연동 채널 키를 넣기 전까지는 테스트 채널로만 결제되고, 주문은 계속 관리자·허용목록 계정에만 열려 있다.
